## 想清楚（MVP 边界 · 需求蔓延）

> 本阶段 4 条：1, 2, 3, 34 —— 都属于「动手前没想清楚边界/需求」导致的返工。

### 1 上来就想做全，结果哪都做不完
- **踩坑概率**：★★★★★（几乎 100%）
- **状态**：持续警惕
- **现象**：收藏了一堆别人的工作台截图，想一口气做 8 个模块，两周后一个都没跑通。
- **我的亲历**：第二大脑从 0 开始直接上了 13 个模块（随想、时间轴、饮品、记账、体重、习惯、OKR、计划、跳舞、实习、市场、AI日报、首页）。早期「工作/金融/跳舞/实习」等功能性不高，基本空壳；OKR、习惯、首页反复返工 5 轮以上才定型。如果不是先用生活记录类模块跑通 MVP，项目早就死在半路上。
- **方案**：
  1. 先写一页纸 PRD：每个模块只保留「没有就活不下去」的功能；
  2. 所有「自动化/定时/复杂联动」一律后置，用「惰性触发」替代；
  3. 第一版只跑通 1 个核心动作（这里是习惯打卡），跑通一周再加第二个。
- **怎么和 AI 说**："我想新增一个模块，先帮我判断这是不是 MVP 必须功能，并列出可以后置到第二版的能力。"

### 3 跳过原型直接写功能，审美/布局反复返工
- **踩坑概率**：★★★★☆
- **状态**：持续警惕
- **现象**：一上来就写逻辑，写完后发现页面丑、布局不对、信息层级混乱，改样式比重写功能还累。
- **我的亲历**：首页统计卡片从「4 个数字」到「可点打卡卡」再到「2×2 大卡片」返工 3 轮；习惯模块的卡片/心情行/日期导航也调了 5 轮以上才定稿。每次都是因为先写了 JS 再调样式，导致结构被功能绑死。
- **方案**：
  1. 新模块先做 1-2 个纯静态 HTML 原型，确认视觉和信息层级后再写数据逻辑；
  2. 用「截图/参考图」给 AI 当验收标尺，而不是只用文字描述；
  3. 复杂布局先在桌面端+手机端分别截图确认，再绑定真实数据。
- **怎么和 AI 说**："我要新增 XX 模块，先不要写任何 JS 逻辑，根据我上传的参考图出 2 个静态原型（桌面+手机），确认视觉后再写数据。"

### 34 认知模块别做成"手动书签笔记本"，要做成"消化引擎"
- **踩坑概率**：★★★★☆
- **状态**：已解决（产品方向）
- **现象**：一开始把认知模块做成"粘贴链接+标题+笔记+标签"的手动录入笔记本，和抖音收藏夹是同一个东西——只换了个存放位置，收藏的内容照样不回看。
- **我的亲历**：第一版认知模块有「+ 添加」弹窗，手动填链接/标题/笔记存成书签。后来意识到这等于把抖音的"黑洞"搬到工作台，毫无意义；真正要的是把收藏内容"消化掉"。
- **方案**：砍掉手动「+ 添加」录入（连同右下角 FAB 的手动新增），认知模块只保留一个入口——顶部「粘贴视频链接，一键智能消化」（下载→本地转写→AI 提炼→入库→待消化队列）。新增统一走这条消化链路，不再有手动书签。
- **怎么和 AI 说**："认知模块不要做成手动书签笔记本，要做成消化引擎：去掉 + 添加 手动录入，只留粘贴链接一键消化。"

### 35 rapidocr 装不上：和 opencv-python 依赖互踩
- **踩坑概率**：★★★☆☆
- **状态**：已解决
- **现象**：`pip install rapidocr-onnxruntime` 后 import 报缺 `cv2` 或被覆盖，OCR 跑不起来。
- **我的亲历**：直接装 rapidocr 会顺带拉一个和已装 onnxruntime 不兼容的 opencv，导致后续 import 失败；反过来先装 opencv 又会覆盖 rapidocr 需要的那份。

- **怎么和 AI 说**："装 rapidocr-onnxruntime 报 cv2 缺失/被覆盖，先装 opencv-python-headless 和 pyclipper/shapely/pillow/six，再用 --no-deps 装 rapidocr。"

### 54 合成产物回流原料池 → 回声室 / 模型坍缩（架构债）

- **踩坑概率**：★★★★★（架构债，随时间复利恶化）
- **状态**：持续警惕（架构债）
- **现象**：吸收卡自动化的「选料」把 AI 自己上周产出的卡片又当新料吃一遍，输出逐期同质化，越喂越像。
- **我的亲历**：吸收卡选料规则「tag 含 AI/科技 直接算」→ 自身产物（absorption-ai / collision / digest-weekly）100% 命中被当新料再吃；每周全量重扫，37.5% 是嚼过的老料。确定性算法 + 静态输入 = 输出逐期同质化（数学必然，非 bug）。

### 53 启动脚本端口检测误判：远程 8080 连接被当成本地占用
- **踩坑概率**：★★★★☆
- **状态**：已解决
- **现象**：双击 `启动工作台.bat` 提示「Port 8080 is in use」，重启电脑再开还是一样，浏览器访问 `localhost:8080` 报 `ERR_FAILED`。
- **我的亲历**：电脑卡死后强制关机，再开机双击 BAT 就报 8080 被占用；实际 `netstat` 里只有一个 UDP 连接到远程 `42.187.183.162:8080`，并没有本地进程在监听 8080。BAT 里用 `findstr ":8080 "` 检测，把任何含 `:8080` 的连接（包括对外连接）都当成「本地占用」，触发误报。
- **方案**：把 BAT 的端口检测改成只匹配本地 `LISTENING` 状态，具体用 `findstr /R` 匹配 `0.0.0.0:8080...LISTENING`、`127.0.0.1:8080...LISTENING`、`[::]:8080...LISTENING` 三行；这样远程 UDP/TCP 连接不会触发误报。
- **怎么和 AI 说**："启动工作台.bat 提示 Port 8080 is in use，但 netstat 没有本地 LISTENING，只有对外 8080 连接，帮我修 BAT 的端口检测，让它只判断本地监听状态。"

### 43 删除/合并漏 tombstone → 跨设备删除无效、老数据复活
- **踩坑概率**：★★★★★
- **状态**：已解决
- **现象**：在手机上删了某条记录（习惯 / 日志等），电脑端还在；或直接改 master.json 清数据，另一台设备 sync 后又把老数据拉回来。
- **我的亲历**：①11 个模块的删除函数只动 data store、没写 `DB.tombstones`；②`server.py` 合并只比 `updatedAt`、不看 tombstone，设备上传的老数据会覆盖清理结果 → 删了又活。修完 server 合并逻辑还必须**重启 server** 才生效。
- **方案**：所有删除函数同时写 `tombstones`；`server.py` 合并时优先采纳 tombstone（被删记录不回灌）；改完删逻辑后重启 server。**改已存在记录的 gid 时，必须把 `updatedAt` 设为 `now + 1000s` 以上**——否则 client 认为「没更新」不覆盖，改动不生效、老 gid 还在。
- **怎么和 AI 说**："某条记录在手机删了电脑还在，帮我查删除函数是不是漏写 DB.tombstones，以及 server 合并是否忽略了 tombstone 只比 updatedAt；改旧 gid 记得把 updatedAt 设为 now+1000s 否则客户端不覆盖。"

### 44 flex 滚动陷阱：flex:1 + overflow-y:auto 必须加 min-height:0
- **踩坑概率**：★★★☆☆
- **状态**：已解决
- **现象**：手机短屏下 `.content` / `.modal-body` 整页或弹窗内容滚不动，被截断看不到底部。
- **我的亲历**：`.content` 等容器设了 `flex:1; overflow-y:auto`，但缺 `min-height:0`；flex 子项默认 `min-height:auto` 会按内容撑高，被 `body{overflow:hidden}` 裁掉 → 滚动失效。桌面高屏常「看起来正常」，手机短屏必现。
- **方案**：所有 `flex:1 + overflow-y:auto` 的滚动容器补 `min-height:0`；「页面级滚动只有一处 `.content`」，修一处全模块生效。
- **怎么和 AI 说**："手机上某模块内容滚不动、底部被截断，帮我查滚动容器是不是 flex:1 但漏了 min-height:0，导致被 body 的 overflow:hidden 裁掉。"

## 附：跨分类的常驻红线 · 改动前必读

- **不为任何 IndexedDB store 建 `date` 索引**：历史上 `unique:true` 的 date 索引会在多设备同步同日期多条记录时触发 `ConstraintError` 卡死写入；所有按日期查询都在 `getAll` 后前端 filter。
- **跨设备引用必须用 gid**：记录间的引用（如 `dance_logs.songId`、`drink_records.financeId`）一律存 gid，通过 `DB.getByGid` 解析，禁止存本地自增 id。
- **每条记录必须有全局唯一 `gid`**；删除通过 `tombstones` 传播，冲突以 `updatedAt` 最新版本为准；且 **`server.py` 合并时必须看 tombstone**——只比 `updatedAt` 会令老数据覆盖清理结果、删了又活，改完删/合并逻辑要重启 server。
- **前端渲染口径统一用 `habitGid`**（习惯模块的完成数、卡片勾、日期导航、归档弹窗、统计页全部一致），杜绝本地 `habitId` 残留匹配。
- **`server.py` 是常驻静态服务，改前端不重启、不 `taskkill` 整个 python**；启动前先查端口占用避免僵尸进程抢 8080，但检测必须只匹配本地 `LISTENING` 状态，不要简单 `findstr ":8080 "`（会误把远程 8080 连接当成本地占用）；**POST 读取必须 `loop-read` 攒满 `Content-Length`**，不能 `self.rfile.read(length)` 短读（隧道分包会截断 JSON）。
- **不要直接手改 `.sync/master.json`**：server 每 2s 自动备份会把内存数据回写覆盖你的改动；任何数据修改都走 `/api/sync` 或前端，确需改文件先停 server。
- **`flex:1 + overflow-y:auto` 的滚动容器必须加 `min-height:0`**，否则 flex 子项默认 `min-height:auto` 被 `body{overflow:hidden}` 裁掉、手机短屏滚不动。
- 任何 IndexedDB 结构升级（含新增 store）必须配套迁移逻辑，历史数据不丢失；新增 store 会自动纳入 `exportAll/importAll` 与备份。
- **远程 WorkBuddy 默认工作目录是 Claw 沙箱**：所有远程（手机 / IM）下发的文件改动，一律用绝对路径 `G:\_06_项目代码\工作台\...`，否则相对路径会被解析到 `C:\Users\Lenovo\WorkBuddy\Claw` 改错位置。
- **AI 远程只能改磁盘文件、碰不到浏览器 IndexedDB 运行时**：任何「远程把内容塞进网页模块（如认知）」的需求，必须走 server `/api` 或前端 `DB.add` 落库，不能只靠 AI 改磁盘文件。
- **`cloudflared.exe` 必须有完整性校验**：启动隧道前校验 exe 真实大小 ≥ 40MB，残缺文件（如下载中断的 1.31MB）会被 `.cf_ok` 标记误判为已下载而跳过重下，导致隧道起不来；大小不够就删 `.cf_ok` 强制重下。
- **给 LLM 加新输出段/字段，必须同步改所有消费端解析**（如 `SECTION_ORDER` / schema 读取）：否则新能力被静默丢弃——不报错、不崩、但功能没生效，排查极难。改动后用 dry-run 打印全部段验证新段真出现。
- **Python `requests` 出网须做代理端口可用性探测**：环境会残留死代理（如 `127.0.0.1:7890`），`getproxies()` 读到后 PROXY 路径必失败；探测不通就双路走直连，别无脑信残留代理。

# 稳定部署方案（消灭 CloudStudio 换 URL 痛点）

## 问题
CloudStudio 每次重部署会新建工作区、**可能更换 URL**。导致：手机 PWA「添加到主屏幕」的图标指向旧地址失效，需重新添加；手机端「后端服务地址」也得改。

## 目标
拿到一个**固定不变**的前端地址，让 PWA 装一次就永久有效。

## 方案对比

### 方案 A：GitHub Pages（免费、固定子域名，推荐先上）
- 地址形如 `https://<你的GitHub用户名>.github.io/<仓库名>/`，**永久不变**。
- 完全免费，静态托管，天生适合本工作台（纯前端 SPA）。
- 支持自定义域名（方案 B）作为可选项，不强制买域名。
- 后端 `server.py` 仍跑在你本机，前端只负责展示 + 触发消化，跨域已放开，不受影响。

### 方案 B：GitHub Pages + 自定义域名
- 在 A 基础上，买一个域名（如 `secondbrain.example.com`），DNS 解析到 Pages，仓库放 `CNAME` 文件。
- 一次性配置，之后 URL 永久固定且好记。
- 需要：① 一个域名（阿里云/Cloudflare/Namecheap 等，约 ¥50–100/年）；② 能改该域名的 DNS。

### 方案 C：CloudStudio 绑定自定义域名
- 若 CloudStudio 平台支持绑定自有域名，可直接在面板绑定，免去换 URL。
- 依赖平台是否开放该能力，且通常也要自有域名。

## 实施（方案 A 落地步骤）
1. 在 GitHub 新建一个**空仓库**（如 `second-brain-web`）。
2. 本地执行（仓库地址换成你的）：
   ```bash
   cd G:\_06_项目代码\工作台\workspace
   # 初始化并关联（仅首次）
   git init
   git remote add origin https://github.com/<用户名>/second-brain-web.git
   # 把 dist/ 推到 gh-pages 分支
   git checkout -b gh-pages
   git add dist && git commit -m "deploy"
   git push -u origin gh-pages
   ```
   或更简单：用本项目预备的 `tools/deploy_ghpages.py`（自动把 dist/ 推到 gh-pages）。
3. 仓库设置 → Pages → Source 选 `gh-pages` 分支 → 保存。
4. 几分钟后访问 `https://<用户名>.github.io/second-brain-web/`。
5. 手机端重新「添加到主屏幕」，这一次地址**永久不变**。
6. 以后更新前端，只需重跑 `tools/deploy_ghpages.py`（或 push），URL 不动。

> 注：`manifest.webmanifest` 的 `start_url`/`scope` 已用相对路径 `./`，在 GitHub Pages 子路径下正常工作，无需改代码。

## 自动化（可选）
仓库放 `.github/workflows/deploy-pages.yml`，以后本地改完 `dist/` 推到 `main`，GitHub Actions 自动发布到 Pages，连手动推 gh-pages 都省了。

## 决策点（需用户提供）
- 是否有 GitHub 账号？（决定能否走 A/B）
- 是否愿意买域名？（决定要不要 B/C）
- 还是先维持 CloudStudio，只接受偶尔重加 PWA？
